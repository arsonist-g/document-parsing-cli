# 错误与退出码

当一次调用失败时加载本文件，或当你要判断某个失败是否值得重试时加载。入口文件已经承载的内容这里不重复。

失败会向 stderr 打印一行 `error: <消息>`，并设置进程退出码。在调用之前把 `DOCPARSE_DEBUG` 设成任意非空值，上游响应细节会以 JSON 附加到 stderr。对 `parse`、`flash`、`task` 而言，调用失败时 stdout 保持为空，所以要读的是退出码，不是输出；退出码 7 是例外，成功的那些路径已经在 stdout 上。管理类命令不一样，`account test`、`quota`、`doctor` 会把报告打到 stdout，然后以失败的码退出。

## 退出码

| 码 | 类别 | 含义 | 处置 |
|---|---|---|---|
| 0 | 成功 | 调用完成。 | 读打印出来的路径。 |
| 1 | 内部 | 工具自身的缺陷。 | 连同消息一起上报。 |
| 2 | 参数 | 某个参数、某个值或某个子命令不对。本地文件超出体积上限也在这里被拒，此时还没有任何上传。 | 修正命令行。本地文件的上限在本地判，所以 `-60005` 与 `-30001` 是 URL 来源仍会得到的码。 |
| 3 | 配置 | 配置文件不对，或 `doctor` 的某个检查项不对。 | 跑 `docparse config show` 与 `docparse doctor`。 |
| 4 | 网络 | 上游不可达。 | 重试一次。若重复出现，检查到 `base_url` 的网络路径。 |
| 5 | 账号 | 账号池里每个账号都被拒绝，或没有配任何账号（`parse` 遇到空池就是这个码；`task`、`batch`、`quota` 没有账号时退出码是 2）。 | 跑 `docparse account test`，然后修凭证。重试不会改变结果。 |
| 6 | 上游 | 文档失败、提交失败，或等待超时。 | 记住消息里的 `task_id`，用 `docparse task <task_id>` 重新查询；`batch_id` 用 `docparse batch <batch_id>` 重新查询。不要重新提交文档。 |
| 7 | 部分成功 | 这次调用里有部分文档成功。 | 已经打印的路径依然有效。只重新提交失败的那些输入。 |

## 上游错误码

这些码来自厂商，出现在消息里。「重试」列写的是工具拿这个码怎么办，以及剩下要你做什么；入口表里也有的码两处都会出现，入口给的是更短的版本。

| 码 | 含义 | 重试 |
|---|---|---|
| `A0202` | Token 错误。 | 仅可换账号。 |
| `A0211` | Token 已过期。 | 仅可换账号。 |
| `-500` | 参数或 Content-Type 错误。 | 否。 |
| `-10001` | 上游服务异常。 | 是。 |
| `-10002` | 请求参数格式错误。 | 否。 |
| `-60001` | 生成上传 URL 失败。 | 是。 |
| `-60002` | 文件类型不支持。 | 否。 |
| `-60003` | 文件读取失败。 | 否。 |
| `-60004` | 文件为空。 | 否。 |
| `-60005` | 文件超过 200 MB 上限。 | 否。 |
| `-60006` | 文档超过 200 页上限。 | 否。 |
| `-60007` | 解析模型暂不可用。 | 是。 |
| `-60008` | 厂商没能在时限内读取你的来源 URL。 | 否。改为下回文件再上传。 |
| `-60009` | 提交队列已满。 | 是。 |
| `-60010` | 解析失败。 | 是。 |
| `-60011` | 没找到有效文件，说明上传没落地。 | 否。 |
| `-60012` | 任务不存在，或已过期。 | 否。 |
| `-60013` | 任务属于另一个账号。 | 换提交它的那个账号。 |
| `-60015` | 文件无法转换成可解析的形式。 | 否。先自行转成 PDF。 |
| `-60016` | 转换成额外导出格式失败。 | 否。去掉那个格式。 |
| `-60018` | 厂商拒绝了这次调用：当日页数额度已用完。 | 次日，或换账号。账号池会冷却该账号到次日、优先用别的账号，但没有别的可用账号时仍会回头用它，所以只有一个账号时当天重试照样会被发出去。 |
| `-60019` | HTML 额度不足。 | 次日，或换账号。 |
| `-60020` | 含义未知：厂商没有文档，工具也没有它的释义。 | 是。 |
| `-60021` | 读取页数失败。 | 是。 |
| `-60022` | 抓取网页失败，常因限频。 | 是。 |
| `-30001` | 输入超过 `flash` 的 10 MB 上限。 | 改用 `parse`。 |
| `-30002` | `flash` 通道不支持该文件类型。 | 改用 `parse`。 |
| `-30003` | 输入超过 `flash` 的 20 页上限。 | 改用 `parse`。 |
| `-30004` | `flash` 请求参数非法。 | 否。 |
| 任意 `5xx` | 上游返回服务端错误。 | 是。 |

## 重试

- 可重试的码会先在另一个账号上重试，因为账号池会分散调用，并冷却失败的账号。这正是你很少见到它们的原因。
- `A0202`、`A0211`、`-60018`、`-60019` 同时会冷却该账号，于是有别的可用账号时账号池不再优先选它，全都不可用时仍会回头用它。这就是为什么换掉凭证之后退出码 5 仍会出现：要新增账号，而不是重试旧账号。
- 厂商又把页数额度描述成「最高优先级解析额度」，说用完后仍会以降级优先级继续服务，而上一条拒绝是明确的。`-60018` 之后是否还留有一份降级额度，文档没有定论；账号池当天不再优先选它，当天重试仍可能成功。
- 不可重试的错误，例如 `-60002`，会立即终止调用，因为换一个账号得到的还是同一个答复。
- 两张表都没有的码按「该文档致命」处理：保留消息，没有理由就不要重新提交。若反复出现，连同错误码一起上报。
- 可重试路径穷尽后，浮出来的是最后一次真实失败，不是替代品。在 `parse`、`quota`、`account test` 上，凭证被拒或过期以退出码 5 结束；`task` 与 `batch` 遇到它会换账号，最终以退出码 6 结束。其余上游失败一律以退出码 6 结束，厂商给了错误码时，码就留在消息里。
